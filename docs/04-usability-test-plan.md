# 04｜可用性测试计划

## 1. 测试目的

验证用户能否发现并理解探索入口、做出方向选择、识别临时影响范围、使用反馈并顺利退出。测试目标是发现交互和理解问题，不是证明信息多样性或留存提升。

## 2. 参与者

- 计划招募 6–8 名经常使用短视频推荐流的成年人，覆盖不同主动搜索习惯。
- 首轮属于探索性测试，样本用于发现问题，不代表总体用户。
- 不采集不必要的敏感个人信息；录音/录屏前先征得同意。

## 3. 测试形式与材料

- 远程屏幕共享或线下观察，单人约 30–40 分钟。
- 材料：可点击低保真原型、任务脚本、观察记录表、测试后访谈问题。
- 主持人不提前讲解按钮含义；参与者可边操作边说出想法。

## 4. 开场说明

“今天测试的是一个早期概念原型，不是在考你。请按平时使用短视频的方式操作，并说出你在想什么。过程中我不会马上解释页面，如果卡住请告诉我你期待看到什么。”

## 5. 任务脚本

### 任务一：找到入口

“你刚看完一条关于城市徒步的视频，想看看这个兴趣还能延伸到哪里。请继续操作。”

观察：入口发现时间、误点、是否先寻找搜索、对入口文案的理解。

### 任务二：选择方向

“你希望看到与城市徒步有关、但不完全相同的内容。请选一个你觉得合适的方向，并说说你认为接下来会发生什么。”

观察：方向理解、选择理由、是否理解本次探索范围。

### 任务三：反馈内容

“当前出现的探索内容有些不符合你的兴趣，请告诉产品你希望怎样调整。”

观察：反馈按钮发现率、反馈含义理解、是否担心改变长期推荐。

### 任务四：退出并返回

“你现在想结束探索，回到刚才的视频。”

观察：退出路径、是否能回到原位置、是否出现迷失或误解。

## 6. 记录指标

- **任务完成：** 独立完成 / 提示后完成 / 未完成。
- **完成时间：** 从任务开始到完成关键操作的时间。
- **错误与犹豫：** 误点、来回切换、停顿和请求澄清。
- **理解：** 用户能否复述探索方向及影响范围。
- **主观体验：** 入口可发现性、控制感、相关性预期、退出信心（1–5 分量表，仅作描述）。
- **原话：** 记录有助于解释行为的原句，不记录可识别身份的信息。

## 7. 测试后问题

1. 你觉得「拓展这个兴趣」会做什么？
2. 三个探索方向有什么区别？哪个最适合你的目标？
3. 你认为这次操作会不会永久改变推荐？为什么？
4. 哪一步最不清楚或最费力？
5. 你会在什么情况下使用它？什么情况下不会？
6. 你最希望增加、删除或改写什么？

## 8. 分析与迭代

- 先按任务整理问题，再按严重程度排序：阻断完成、造成误解、增加明显操作成本、轻微文案问题。
- 找到跨参与者重复出现的问题，优先修复流程和状态表达；个别意见作为待观察信号，不直接当作普遍需求。
- 每次迭代记录：问题证据、设计修改、预期影响、仍需验证事项。
- 不以小样本满意度分数推断整体业务效果。
